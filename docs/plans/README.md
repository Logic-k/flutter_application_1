# MemoryLink 실행 계획 문서

- **계획 기준일:** 2026-08-30
- **상태:** 실행 정본(canonical execution plan)
- **적용 범위:** 현재 저장소의 감사 결과를 기준으로 한 출시 안전, 플랫폼 강화, 기존 데이터 가치화, 보행 검증

## 정본 선언

이 디렉터리의 문서가 향후 작업의 **실행 순서·Gate·완료 조건 정본**이다. 루트의 `DEVELOPMENT_ROADMAP.md`, `PROGRESS.md`, `RELEASE_CHECKLIST.md` 및 기타 설계 문서는 역사·배경 참고자료로 유지한다. 서로 충돌할 때에는 먼저 현재 코드와 재현 결과를 확인하고, 그다음 이 계획의 Gate를 적용한다. 이 선언은 기존 문서를 폐기하거나 수정한다는 뜻이 아니다.

## 읽는 순서

1. [00 마스터 실행계획](00_MASTER_EXECUTION_PLAN.md): 기준선, 종속성, 일정, Go/No-Go
2. [01 Stage 1 출시 안전](01_STAGE_1_RELEASE_SAFETY.md): 출시 전에 제거해야 할 안전·규제·개인정보 위험
3. [02 Stage 2 플랫폼 보안](02_STAGE_2_PLATFORM_SECURITY.md): Firestore, AI, FGS, 인증, 관측성
4. [03 Stage 3 제품 가치](03_STAGE_3_PRODUCT_VALUE.md): 이미 수집한 데이터의 사용자 가치와 접근성
5. [04 Stage 4 보행 검증·연구](04_STAGE_4_GAIT_VALIDATION_RESEARCH.md): 실기기 측정 검증과 외부 노출 승격 기준
6. [05 근거 등록부](05_RESEARCH_EVIDENCE_REGISTER.md): 공식 정책·법령·연구, 적용 한계, 재검증 상태
7. [06 힉스필드 시각 품질 고도화](06_HIGGSFIELD_VISUAL_UPGRADE.md): Stage와 독립된 별도 트랙. 게임 피드백 기반 → 힉스필드 일러스트·아이콘·SFX → 랜딩·스토어·발표 시각물
8. [07 flutterfx 모션·피드백 고도화](07_FLUTTERFX_MOTION_UPGRADE.md): 별도 트랙 F. 06의 트랙 A(게임 피드백)를 흡수. 모션 토큰·축소 모션 게이트 → GameTemplate 공통 피드백 → 완료 축하 → 진입·목록·진행 지표 → AI 채팅 타이핑
9. [08 앱 전역 모션 시스템·랜딩 고도화](08_MOTION_SYSTEM_GLOBAL.md): 별도 트랙 G. 07 이후 앱 전역(스플래시·로그인·온보딩·대시보드·목록·차트·스켈레톤·예측형 뒤로가기)으로 확장. 딥리서치 결론(의존성 0 유지, 축소 모션 3단, 전환 덮어쓰기 금지)과 Opus 5.5 실행 프롬프트 수록

## 실행 원칙

- 순서는 `Gate 0 계획 동결 → Stage 1 출시 안전 → Stage 2 플랫폼 강화 → Stage 3 제품 가치 → Stage 4 보행 검증/연구`로 고정한다.
- **필수**는 해당 Gate 통과 전 완료, **권장**은 같은 Stage 내 우선 처리, **향후**는 선행 Gate 통과 뒤 착수한다.
- 제품 경계는 **비의료 생활습관 지원·훈련·기록·자가 모니터링**이다. 진단, 선별, 치료, 치매 예방 보장, 조기 발견, 고위험 판정 표현을 사용하지 않는다.
- 보행 CV는 MemoryLink 구현 자체의 검증이 끝나기 전 리포트, 보호자 공유, 임상 위험 표시, 마케팅 근거로 사용하지 않는다.
- Firebase AI Logic과 사용자 API key를 사용하는 Gemini 일반 REST 직접 호출은 다른 경로다. App Check가 후자를 자동 보호한다고 간주하지 않는다.
- Firestore TTL은 지연·비트랜잭션 삭제이며 하위 컬렉션을 지우지 않으므로 계정 삭제 완료 수단으로 단독 사용하지 않는다.
- 근거는 `공식 의무`, `공식 권장`, `연구 결과`, `프로젝트 판단`으로 구분한다. 연구의 모집단·개입·결과를 앱에 그대로 일반화하지 않는다.
- 기존 미추적 파일은 사용자 작업 상태다. 각 구현 PR은 관련 파일만 명시적으로 스테이징한다.

## 변경 통제

각 작업 패킷은 코드 변경 전에 다음 산출물을 남긴다: (1) 이슈/ADR, (2) 영향 데이터·권한 목록, (3) 테스트 추가 계획, (4) 롤백 방법. 완료 증거는 PR 또는 릴리스 기록에 명령 출력, 스크린샷, Play/App Store 선언 사본, 실기기 모델·OS를 첨부한다.

## 현재 기준선의 성격

감사 시점에 Flutter 3.41.5/Dart 3.11.3, release merged manifest `targetSdkVersion=36`, `flutter analyze` error·warning 0/info 4, 단위·위젯 테스트 307/307 통과가 확인되었다. 이 수치는 계획의 출발점이지 영구 보증이 아니다. 구현 시작과 출시 후보마다 [마스터 계획의 재현 명령](00_MASTER_EXECUTION_PLAN.md#재현-명령)으로 갱신한다.
