# ADR-001 첫 출시 범위

> 결정 2026-10-04 · 사용자 지시 "남은 출시 차단 항목도 권고안대로 진행해주세요"
> 근거 문서: `docs/LAUNCH_AUDIT_2026-09-28.md`(로컬 사본, 미추적) P0-01

## 배경

출시 감사 P0-01은 "출시 기능 범위가 동결되지 않아 Play 신고와 바이너리가 계속 어긋난다"고 지적했다.
이 문서는 첫 공개 출시(RC)에 무엇을 켜고 끄는지 한 곳에 고정한다. 신고(`PLAY_CONSOLE.md`),
처리방침(`site/privacy.html`·`landing/privacy.html`), 코드는 이 표를 따른다.

## 결정

| 기능 | 첫 출시 | 근거·조건 |
|---|---|---|
| 생성형 AI 대화(Gemini) | 끔. 개발 빌드에서만 켤 수 있음(`ENABLE_GENERATIVE_AI`) | P0-10. 인앱 신고·키 보관·약관이 갖춰지기 전에는 켜지 않는다 |
| 온디바이스 AI(Gemma) | 제거 | P0-11. 16KB 기기 비호환, 1.5GB 모델, 미완 기능 |
| AI 대화 화면 | 규칙 기반 응답 | 대화를 저장·전송하지 않는다 |
| Health Connect(Android) | 쓰지 않음, 권한 미선언 | P0-09. iOS HealthKit 백그라운드 읽기는 유지 |
| 걸음 측정 | 사용자가 켤 때만, 재부팅 자동 시작 끔 | P0-03. 상시 알림은 "걸음 측정 중" |
| 보호자 안심 연결 | 켬(v2) | P0-05. 128비트 토큰, 30일 만료, 이름·걸음·점수만 공개, 매일 정리 작업 |
| 보호자 링크 열기 | 브라우저 전용, App Link 없음 | P0-13 |
| 음성 평가 | 차단 화면 유지 | 정확도 개선 전까지 |
| 일기 알림 | 기본 꺼짐, 켤 때 권한 요청, 부정확 예약 | P0-04 |
| 활동량 이상 알림 | 누르면 받는 사람·내용 확인 뒤 문자 앱 열기 | P0-04. 알림에 전화번호를 싣지 않는다 |
| 계정 삭제 | 앱 안 "계정과 모든 데이터 삭제" + 웹 안내 | P0-07 |
| release 서명 | 업로드 키가 없으면 빌드 중단 | P0-14 |
| 클라우드 백업 | 끔(기기 간 직접 전송은 DB만) | P0-07 |

## 다시 켜는 조건

- **생성형 AI**: AI 응답마다 인앱 신고, 신고 처리 절차, 건강·진단 답변 금지와 위기 안내 테스트,
  전송 직전 별도 동의, 키를 보안 저장소로 옮기기(P0-10 1~10). 그 뒤 신고·처리방침을 함께 고친다.
- **온디바이스 AI**: 16KB 정렬된 엔진, 모델 무결성 확인과 저장 공간 안내. `scripts/check_16kb.py` 통과.
- **Health Connect**: Android에서 실제로 READ_STEPS를 요청·사용할 때만. WRITE는 쓰지 않는다.

## 이 결정 밖에 남은 출시 차단 항목

| 항목 | 상태 | 누가 |
|---|---|---|
| P0-00 패키지·개발자 신원 확인 | Play Console에서 확인 | 사용자 |
| P0-02 CI·E2E | Maestro 목록은 고침. 통합 테스트 로그인 단언, PR 게이트 분리, API 36·16KB 이미지 작업은 남음 | 개발 |
| P0-15 비의료 표현 | 앱 화면의 "임상 리포트·의료진용·음성 진단"이 게이팅 Maestro 셀렉터라 바꾸기 전에 보고가 필요하다(저장소 규칙) | 사용자 결정 |
| P0-16 스토어 자산 | 기능 그래픽(1024×500)과 새 스크린샷 | 사용자 |

## 출시 때 함께 할 일

- 새 빌드를 배포할 때 처리방침 6번과 삭제 안내 페이지에 "설정 → 계정과 모든 데이터 삭제"를 추가하고
  Hosting·Pages에 배포한다. 기능이 사용자 손에 가기 전에는 공개 문서에 쓰지 않는다.
- 출시 AAB로 `python scripts/check_16kb.py`와 병합 매니페스트 권한을 다시 확인한다.
