새 결함

포털이 꺼진 빌드에서 온보딩 가드가 우회됩니다

  • 대상: 관리자 포털이 꺼진 빌드(ADMIN_CODE_SHA256를 넣지 않은 릴리스)에서, 로그인했지만 온보딩을 마치지 않은 사용자.
  • 현상: 이 사용자가 /admin*로 들어오면 동의 화면(/consent)이 아니라 메인(/)에 도착합니다.
  • 원인: go_router 17의 top-level redirect는 "내비게이션당 최대 한 번" 실행됩니다. 포털 가드가 돌려준 /는 다시 평가되지 않아 온보딩 가드를 건너뜁니다.
  • 처리: 기대 동작(/consent)을 적은 skip 테스트로 남겼습니다. --run-skipped로 강제 실행하면 결함이 재현됩니다. 고치려면 라우터 로직을 바꿔야 하므로 디자인 PR과 분리한 별도 기능 PR로 제안합니다.

G4 앞에서 멈춘 이유

G0~G3는 기존 화면에 영향이 없는 단계입니다. 테스트, 새 토큰, 연결하지 않은 컴포넌트만 추가했습니다. 반면 G4(AI Chat → Reports → Walking → Health → Diary → Guardian → Register)부터는 실제 화면의 상태 처리와 모양이 바뀝니다. 위 결정 사항(그림자 색, TextButton 대비, 보호자 화면 결함)이 G4 결과에 직접 들어가고, 컴포넌트의 시각 방향도 먼저 확인받는 것이 맞다고 판단했습니다. 확인해 주시면 DS-006 AI Chat의 오류·로딩 상태부터 시작합니다.
