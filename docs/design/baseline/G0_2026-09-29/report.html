보호자 안심 연결 화면이 에뮬레이터 빌드에서 항상 오류 화면

  • 화면에 [core/no-app] No Firebase App '[DEFAULT]' has been created가 뜹니다.
  • lib/main.dart:100의 if (isEmulator) return;이 IS_EMULATOR=true 빌드에서 Dart 쪽 Firebase.initializeApp()을 의도적으로 건너뜁니다. 네이티브 초기화는 logcat상 성공했습니다.
  • guardian_link_screen.dart:20이 필드 초기화에서 GuardianSyncService()를 만들고, 서비스(:32)가 곧바로 FirebaseFirestore.instance를 읽습니다. FirebaseService.isAvailable 확인이 없어 화면 생성 시점에 예외가 납니다.
  • 게이트 공백: guardian_link_flow는 내 정보 탭의 카드 문구만 확인하고 화면에는 들어가지 않아 PASS였습니다.
  • 실기기에서 Firebase 초기화가 실패하는 경로에서도 같은 구조입니다. 실기기 재현은 하지 않았습니다. 핸드오프 §9-4(토큰 생성 실패 시 QR 로딩 고정)보다 앞단이며, DS-013·G4 Guardian 작업에서 가장 먼저 볼 대상입니다. 이번에는 고치지 않았습니다.

predictive back opt-in 부재 — 영향은 Android 13~15 기기

  • 설치 APK의 targetSdk는 36입니다(Flutter 3.41.5 기본값). Android 16 동작 변경 문서에 따르면 targetSdk 36 앱은 Android 16 이상 기기에서 플래그 없이도 시스템 predictive back 애니메이션이 기본으로 켜집니다. 플래그 부재가 실제로 영향을 주는 것은 Android 13~15 기기입니다.
  • 별도 플랫폼 PR 대상입니다. 앱 내부 route 전환은 pageTransitionsTheme 추가 금지 규칙과 함께 판단해야 합니다. 근거 문서

  • 기준선을 버리려면 docs/design/baseline/G0_2026-09-29/를 지우면 됩니다(미추적).
